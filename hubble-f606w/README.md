# hubble-f606w — HST F606W drizzled mosaics

Test cases extracted from public Hubble Space Telescope drizzled mosaics
(`calib_level=3`) taken through the **F606W "Wide V"** filter — the
workhorse ACS/WFC + WFC3/UVIS broadband, backbone of HUDF, GOODS,
COSMOS, CANDELS, etc. F606W: pivot 590 nm, FWHM 230 nm.

Each `<obs_id>.json` follows `zodiacal::extraction::SourcesJson` (drop-in
input for `zodiacal batch-solve`) plus an `hst` block with archive
provenance.

## Pipeline

The cases were generated by the
[`hst_f606w_extract`](../../starfield-datasources/crates/mast/src/bin/hst_f606w_extract.rs)
binary in the `starfield-datasources` workspace. Per observation:

1. Cone-free MAST query via `Mast.Caom.Filtered` for
   `obs_collection=HST`, `filters=F606W`, `dataproduct_type=image`,
   `calib_level=3`, `dataRights=PUBLIC`.
2. Fetch the data-product list for the observation.
3. Pick the SCIENCE FITS, preferring `*_drc.fits` (CTE-corrected
   drizzled) over `*_drz.fits`.
4. Download to `~/.cache/starfield/mast/`.
5. Read CRVAL1/CRVAL2 + CD matrix (linear WCS) from the FITS via
   `starfield_mast::Wcs::read_from_fits`.
6. Run `zodiacal extract <fits> -o tmp.json --threshold-sigma 5.0
   --max-sources 200 --ra <crval1> --dec <crval2> --plate-scale
   <sqrt(|det(CD)|) * 3600>`.
7. Read tmp.json, splice in the `hst` metadata block (see schema
   below), atomically rename to `<obs_id>.json`.
8. Delete the FITS so the cache stays bounded.

49 observations are processed concurrently — just under MAST's
documented 50-connection soft limit. Transient HTTP/MAST errors are
retried with exponential backoff (5s → 30s → 2 min → 10 min → 30 min).

The run is **resumable**: re-running short-circuits any obs whose
`<obs_id>.json` already exists, so paging through MAST again is the
only re-cost.

## Schema

```json
{
  "image_width":  4214.0,
  "image_height": 4239.0,
  "ra_deg":       195.40950548468996,
  "dec_deg":      27.795445815100507,
  "plate_scale_arcsec": 0.05,
  "sources": [
    { "x": 2107.5, "y": 2118.0, "flux": 12.34 }
  ],
  "hst": {
    "obs_id":            "jbrv14010",
    "obsid_internal":    "26431926",
    "obs_collection":    "HST",
    "instrument_name":   "ACS/WFC",
    "filters":           "F606W",
    "target_name":       "FRONTIER-FIELD-MACS-J0717.5+3745",
    "proposal_id":       "13386",
    "proposal_pi":       "Lotz, Jennifer",
    "t_exptime":         2392.0,
    "t_min_mjd":         56945.50,
    "t_max_mjd":         56945.55,
    "product_filename":  "jbrv14010_drc.fits",
    "product_uri":       "mast:HST/product/jbrv14010_drc.fits",
    "image_url":         "https://mast.stsci.edu/api/v0.1/Download/file?uri=mast:HST/product/jbrv14010_drc.fits",
    "preview_url":       "https://mast.stsci.edu/api/v0.1/Download/file?uri=mast:HST/product/jbrv14010_drc.jpg",
    "mast_archive_url":  "https://mast.stsci.edu/search/ui/#/hst/results?obs_id=jbrv14010"
  }
}
```

The filename `<obs_id>.json` is the MAST `obs_id` — pasting it into
`mast_archive_url` (or feeding it to `astroquery.mast.Observations.query_criteria(obs_id=...)`)
returns the original observation row; `product_uri` is the verbatim
MAST URI for the FITS itself.

## Caveats

- **Flux units**: `zodiacal extract` reads FITS via `fitsio_pure`'s
  compat API (BSCALE/BZERO applied) into `f32` ADU. Drizzle outputs are
  in electrons/sec, so `flux` here is the per-component sum of ADU
  values *as the drizzled FITS encoded them* — not directly comparable
  to the PNG-normalised fluxes in `set2-dr3-mag19/`.
- **Plate scale** is computed as `sqrt(|det(CD)|) * 3600`, the standard
  small-FOV approximation. For drizzled HST products the CD matrix is
  already distortion-corrected, so this number is exact at the
  reference point and accurate to a few percent edge-to-edge.
- **`max-sources` cap**: `zodiacal extract` is run with
  `--max-sources 200`. Crowded fields therefore return their brightest
  200 detections, not all detections.
- **Empty source lists**: a small fraction of WFPC2/PC drizzles (the
  oldest `u*` rootnames) have unusual data layouts that defeat the
  default 5-sigma threshold; their JSON has `"sources": []`. They're
  preserved rather than dropped so the back-index stays complete.
- **Heterogeneous geometry**: image dimensions and plate scale vary
  per-obs (ACS/WFC ~0.05"/px on 4kx4k; WFPC2 ~0.046"/px on 4kx4k;
  WFC3/UVIS ~0.04"/px on 4kx4k). Solver harnesses that previously
  assumed the constant set2 geometry should treat each case
  individually.

## Reproducing

```bash
# in starfield-datasources/
cargo build -p starfield-mast --features bin --bin hst_f606w_extract --release

# in zodiacal/  (FITS feature is on by default)
cargo build --release

# run (resumable; re-running picks up where it left off)
starfield-datasources/target/release/hst_f606w_extract \
    --output-dir zodiacal-test-cases/hubble-f606w \
    --zodiacal-bin zodiacal/target/release/zodiacal \
    --concurrency 49
```

Total observations matching the filter at generation time: **78,414**
(MAST `Mast.Caom.Filtered` `rowsFiltered`, 2026-05-08).
