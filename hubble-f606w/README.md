# hubble-f606w — HST F606W drizzled mosaics

Test cases extracted from public Hubble Space Telescope drizzled mosaics
(`calib_level=3`) taken through the **F606W "Wide V"** filter — the
workhorse ACS/WFC + WFC3/UVIS broadband, backbone of HUDF, GOODS,
COSMOS, CANDELS, etc. F606W: pivot 590 nm, FWHM 230 nm.

Each `<obs_id>.json` follows `zodiacal::extraction::SourcesJson` (drop-in
input for `zodiacal batch-solve`) plus an `hst` block with archive
provenance and an `extraction` block recording how the sources were made.

## Re-extraction (2026-10)

Every case was re-extracted in October 2026 with
[`scripts/reextract_hst.py`](../scripts/reextract_hst.py), using a
`zodiacal extract` built from zodiacal `a006186`. That commit includes
zodiacal#144, which fixes NaN handling in the background estimator.

**Why:** drizzled products pad the area outside the exposure footprint with
NaN (7–33% of pixels). The old extractor sorted every pixel with a
NaN-tolerant comparator that never really sorted, so the background median
and MAD came out NaN or badly wrong. That gave either zero detections or a
skewed threshold. About 29% of the original cases had **no sources at all**
(47% of ACS/WFC).

| Instrument | Cases | 0 sources (old → new) | 200 sources (old → new) | Product changed on MAST |
|---|---|---|---|---|
| ACS/HRC | 3,686 | 124 → 0 | 1,694 → 2,007 | 186 |
| ACS/WFC | 22,717 | 10,730 → 0 | 11,007 → 22,138 | 9,608 |
| WFC3/UVIS | 14,939 | 3,808 → 3 | 7,857 → 11,773 | 6,269 |
| WFPC2/PC | 34,331 | 7,552 → 0 | 26,088 → 34,277 | 4,397 |
| **Total** | 75,673 | 22,214 → 3 | 46,646 → 70,195 | 20,460 |

**Products changed on MAST.** Since the set was first built, STScI has
reprocessed many products: the archive's astrometry was realigned to Gaia,
and some products were re-drizzled. The re-extraction reads the pointing,
plate scale and image size from the **current** FITS header. When they
differ from the earlier values, the old ones are kept under
`extraction.product_changed_from`:

- Pointing shifts: median ~4 mas, 99th percentile ~0.8″, maximum ~60″.
- Image size changed for ~6,000 products.
- Plate scale is unchanged everywhere.

The current headers are the better ground truth.

## Gaia census (`_gaia_census.csv`)

A large share of these fields contain too few Gaia stars to be solvable
against Gaia at all. This matters most for the small WFPC2/PC and ACS/HRC
fields at high galactic latitude. `_gaia_census.csv` has one row per case,
produced by [`scripts/gaia_census.py`](../scripts/gaia_census.py) from the
starfield Gaia DR3 G ≤ 20 HEALPix-5 excerpt. It counts Gaia stars inside
two circles, since the cases don't record rotation:

- the **inscribed** circle (`in_*`), a lower bound on stars in the frame;
- the **circumscribed** circle (`out_*`), an upper bound.

Columns:
- star counts at G ≤ 16/18/19/20;
- `out_g20_with_pm`, the number of those stars with a full astrometric
  solution (proper motion present);
- `n_sources`, the number of extracted sources.

| Instrument | Cases | ≥ 10 sources and ≥ 5 Gaia (inscribed) | ≥ 5 Gaia (circumscribed) | Median Gaia G ≤ 20 in / out |
|---|---|---|---|---|
| ACS/HRC | 3,686 | 1,030 (28%) | 1,380 (37%) | 1 / 2 |
| ACS/WFC | 22,717 | 18,696 (82%) | 21,958 (97%) | 12 / 24 |
| WFC3/UVIS | 14,939 | 8,088 (54%) | 10,353 (69%) | 5 / 11 |
| WFPC2/PC | 34,331 | 14,656 (43%) | 18,798 (55%) | 3 / 6 |
| **Total** | 75,673 | 42,470 (56%) | 52,489 (69%) | |

Report solve rates against the solvable subset (or per census bin), not
the raw 75k. Otherwise the number mostly measures Gaia's star density.

## Original pipeline (2026-05)

The section below describes how the set was first generated. The source
lists have since been replaced by the re-extraction above, but the case
selection (which observations, which product per observation) is
unchanged.

The cases were generated by the
[`hst_f606w_extract`](../../starfield-datasources/crates/mast/src/bin/hst_f606w_extract.rs)
binary in the `starfield-datasources` workspace. Per observation:

1. Cone-free MAST query via `Mast.Caom.Filtered` for
   `obs_collection=HST`, `filters=F606W`, `dataproduct_type=image`,
   `calib_level=3`, `dataRights=PUBLIC`.
2. Fetch the data-product list for the observation.
3. Pick the SCIENCE FITS, preferring `*_drc.fits` (CTE-corrected
   drizzled) over `*_drz.fits`.
4. Download to `~/.cache/starfield/mast/`.
5. Read CRVAL1/CRVAL2 + CD matrix (linear WCS) from the FITS via
   `starfield_mast::Wcs::read_from_fits`.
6. Run `zodiacal extract <fits> -o tmp.json --threshold-sigma 5.0
   --max-sources 200 --ra <crval1> --dec <crval2> --plate-scale
   <sqrt(|det(CD)|) * 3600>`.
7. Read tmp.json, splice in the `hst` metadata block (see schema
   below), atomically rename to `<obs_id>.json`.
8. Delete the FITS so the cache stays bounded.

49 observations are processed concurrently — just under MAST's
documented 50-connection soft limit. Transient HTTP/MAST errors are
retried with exponential backoff (5s → 30s → 2 min → 10 min → 30 min).

The run is **resumable**: re-running short-circuits any obs whose
`<obs_id>.json` already exists, so paging through MAST again is the
only re-cost.


`extraction.product_changed_from` is present only when the archived product
differs from the one the set was first built from (see above).

The filename `<obs_id>.json` is the MAST `obs_id` — pasting it into
`mast_archive_url` (or feeding it to `astroquery.mast.Observations.query_criteria(obs_id=...)`)
returns the original observation row; `product_uri` is the verbatim
MAST URI for the FITS itself.

## Caveats

- **Flux units**: `zodiacal extract` reads FITS via `fitsio_pure`'s
  compat API (BSCALE/BZERO applied) into `f32` ADU. Drizzle outputs are
  in electrons/sec, so `flux` here is the per-component sum of ADU
  values *as the drizzled FITS encoded them* — not directly comparable
  to the PNG-normalised fluxes in `set2-dr3-mag19/`.
- **Plate scale** is computed as `sqrt(|det(CD)|) * 3600`, the standard
  small-FOV approximation. For drizzled HST products the CD matrix is
  already distortion-corrected, so this number is exact at the
  reference point and accurate to a few percent edge-to-edge.
- **`max-sources` cap**: `zodiacal extract` is run with
  `--max-sources 200`. Crowded fields therefore return their brightest
  200 detections, not all detections.
- **Empty source lists**: only 3 WFC3/UVIS cases still have
  `"sources": []` after the re-extraction. They're kept so the
  back-index stays complete. The ~22k empty cases in the original set
  were caused by the extractor's NaN bug, not by the data.
- **Heterogeneous geometry**: image dimensions and plate scale vary
  per-obs (ACS/WFC ~0.05"/px on 4kx4k; WFPC2 ~0.046"/px on 4kx4k;
  WFC3/UVIS ~0.04"/px on 4kx4k). Solver harnesses that previously
  assumed the constant set2 geometry should treat each case
  individually.

## Reproducing

### Re-extraction (current source lists)

```bash
# in zodiacal/
cargo build --release --features cli,fits,image-processing --bin zodiacal

# in zodiacal-test-cases/  (resumable; deletes each FITS once its case is written)
scripts/reextract_hst.py --zodiacal ../zodiacal/target/release/zodiacal \
    --out /path/to/new/hubble-f606w --tmp /path/to/scratch --workers 16
```

The full set downloads **12.9 TB** from MAST. The 2026-10 run took about
4 days of wall-clock time on a ~1 Gb/s link, with MAST and the site uplink
as the bottlenecks.

### Original generation (case selection)

The original generator below lives in the `starfield-datasources`
workspace and is no longer maintained.

```bash
# in starfield-datasources/
cargo build -p starfield-mast --features bin --bin hst_f606w_extract --release

# in zodiacal/  (FITS feature is on by default)
cargo build --release

# run (resumable; re-running picks up where it left off)
starfield-datasources/target/release/hst_f606w_extract \
    --output-dir zodiacal-test-cases/hubble-f606w \
    --zodiacal-bin zodiacal/target/release/zodiacal \
    --concurrency 49
```

Total observations matching the filter at generation time: **78,414**
(MAST `Mast.Caom.Filtered` `rowsFiltered`, 2026-05-08).
